ZeroRespond User Guide & Operational Manual

A non-technical, step-by-step handbook designed for IT administrators and first responders handling cyber attacks.

Practical Cyber Defense

Incident Response Without Panic

ZeroRespond gives non-security IT administrators actionable command-level playbooks, automated case logging, and statutory DPDP Act 2023 compliance reporting. Follow this operational guide to detect, contain, and report cyber threats safely.

HANDLING AN ACTIVE EMERGENCY? Jump straight to your active incident case and execute the step-by-step commands in the Playbook. Do not spend time reading documentation during a breach!
Why ZeroRespond Exists

Most Indian colleges, hospitals, SMBs, and NGOs lack a 24/7 Security Operations Center (SOC) or ₹50,000+/year tooling budgets. When an attack strikes, response is typically uncoordinated WhatsApp messaging, leading to compromised evidence and severe regulatory exposure.

ZeroRespond flips the model:

  • Guided for Non-Experts: Replaces vague advice ("isolate host") with exact copy-pasteable terminal commands.
  • 100% Self-Hosted: Runs locally on your own Linux server. No confidential data ever leaves your premises.
  • DPDP Act 2023 Native: Pre-calculates MTTD/MTTR and fills CERT-In 6-hour statutory breach templates automatically.
Three Golden Rules for Responders
Rule 1
Never Reboot Immediately: Rebooting wipes vital volatile memory (RAM), eliminating encryption keys, active network socket states, and malware artifacts required for court evidence.
Rule 2
Isolate Before Disinfecting: Always cut network connectivity via firewall commands first. This prevents ransomware from moving laterally to servers or cloud storage.
Rule 3
Watch the Statutory Clock: Under CERT-In directions, organizations have exactly 6 hours from detection to notify authorities. Log all actions in the case record.

1 Stage 1: How Detection Works in ZeroRespond
Module 1 (Wazuh SIEM)

Wazuh agents continuously monitor event logs on Windows and Linux endpoints. When an event matches one of our 50+ custom correlation rules (e.g., 500 failed SSH logins, mass file renames with .encrypted, unauthorized sudo usage), an alert card appears in the Detection Feed.

What you need to do: Check the urgency badge. If it is Critical or High, click "Start Response" to auto-create an incident case.
2 Stage 2: Managing Your Incident Workspace
Module 2 (Case Manager)

Opening an incident creates a legal record with a unique Case ID (e.g., IR-08). The Case Manager records discovery time (UTC and IST), the assigned IT responder, the affected computer name, and data categories involved.

Why this matters: Every button click and timestamp in this view becomes part of your court-admissible audit trail under the DPDP Act.
3 Stage 3: Running the Actionable Playbook
Module 3 (Playbook Engine)

ZeroRespond automatically binds the matching response guide. Steps are numbered and enforce the ISO 27035 containment order:

  1. Select Platform: Toggle between Linux and Windows to get exact terminal commands for your target system.
  2. Copy Command: Click the "Copy" button. Open your terminal or PowerShell (Run as Administrator) and paste it.
  3. Verify Expected Output: Check the box labeled "What you should see" to confirm the command succeeded.
  4. Advance Step: Click "Done — Next Step" to log the completion timestamp. You can also add notes, skip if not applicable, or click "Undo Step" if needed.
4 Stage 4 & 5: Closure and DPDP Act Reporting
Module 4 (Compliance Generator)

Once the final containment step is marked complete, the case status shifts to "Contained". A prominent green banner appears prompting you to generate the compliance report.

One-Click PDF Generation: Clicking "Generate & View Report" renders the official Jinja2/WeasyPrint PDF, calculates your MTTD/MTTR metrics, validates CERT-In 6-hour SLA compliance, and formats an email ready to send to incident@cert-in.org.in.
Below are the 5 built-in attack playbooks in ZeroRespond with key symptoms and containment procedures.
1. Ransomware Analysis & Response
Severity: Critical · Target MTTR: < 25 mins

Symptoms: Files rapidly changing to .encrypted / .locked, high CPU spikes, ransom note on desktop, outbound beaconing to unknown IPs.

Immediate Step 1: Isolate the Host
Linux: sudo iptables -I INPUT -j DROP && sudo iptables -I OUTPUT -j DROP
Windows: netsh advfirewall set allprofiles firewallpolicy blockinbound,blockoutbound

Subsequent steps: Identify process PID via ps aux or Get-Process $\rightarrow$ preserve memory $\rightarrow$ kill process with kill -9 [PID] $\rightarrow$ block external C2 IP $\rightarrow$ restore clean data from backup.

2. Brute Force / Credential Attack Response
Severity: High · Target MTTR: < 15 mins

Symptoms: Repeated authentication failures (500+ failed SSH/RDP attempts in under 10 minutes from a single IP), account lockouts.

Immediate Step 1: Block Attacker Source IP
Linux: sudo iptables -I INPUT -s [ATTACKER_IP] -j DROP
Windows: New-NetFirewallRule -DisplayName "Block Attacker" -RemoteAddress [ATTACKER_IP] -Action Block

Subsequent steps: Lock compromised accounts with passwd -l [USER] $\rightarrow$ terminate active sessions with pkill -u [USER] $\rightarrow$ force credential reset $\rightarrow$ enable key-based authentication.

3. Privilege Escalation Response
Severity: High · Target MTTR: < 20 mins

Symptoms: Unauthorized user added to sudo or Administrators group, unexpected binary executed with SUID root, Windows Event ID 4672/4728.

Immediate Step 1: Strip Unauthorized Privileges
Linux: sudo deluser [COMPROMISED_USER] sudo
Windows: Remove-LocalGroupMember -Group "Administrators" -Member [COMPROMISED_USER]

Subsequent steps: Audit persistence mechanisms (cron jobs in /etc/cron* and Windows Task Scheduler) $\rightarrow$ inspect /etc/sudoers $\rightarrow$ revoke cached Kerberos tickets.

4. Data Exfiltration Response
Severity: Medium/High · Target MTTR: < 20 mins

Symptoms: Abnormal outbound transfer spikes to unrecognized external IPs or newly registered cloud buckets; unusual bulk archive creation.

Immediate Step 1: Sever Outbound Data Pipe
Linux: sudo iptables -I OUTPUT -d [DESTINATION_IP] -j DROP
Windows: New-NetFirewallRule -DisplayName "Block Exfil Pipe" -Direction Outbound -RemoteAddress [IP] -Action Block

Subsequent steps: Identify socket PID via lsof -i $\rightarrow$ determine compromised database tables or folders $\rightarrow$ tally affected data principals $\rightarrow$ alert DPO.

5. File Integrity Monitoring (FIM) & Web Tampering
Severity: Medium · Target MTTR: < 30 mins

Symptoms: Wazuh FIM rule alerts on modified /etc/passwd, altered web server HTML/PHP scripts, or modified system binaries (hash mismatch).

Immediate Step 1: Quarantine & Lock Permissions
Linux: sudo chmod 000 [TAMPERED_FILE] && sudo chattr +i [TAMPERED_FILE]
Windows: icacls [TAMPERED_FILE] /deny "Everyone":(F)

Subsequent steps: Compare file hash against git repository $\rightarrow$ restore clean file from master branch $\rightarrow$ audit web server access logs for SQL injection or file upload exploits.

The DPDP Act 2023 — Section 8(6)

India's Digital Personal Data Protection Act, 2023 establishes legal accountability for any organization handling personal data (designated as Data Fiduciaries).

Mandatory Duty under Section 8(6):
"In the event of a personal data breach, the Data Fiduciary shall give the Board and each affected Data Principal intimation of such breach in such form and manner as may be prescribed."

Penalties for failure to implement reasonable security safeguards or failure to notify the Data Protection Board can reach up to ₹250 Crores under the Act's schedule.

CERT-In 6-Hour Reporting Mandate

Under the statutory directions issued by the Indian Computer Emergency Response Team (CERT-In) under Section 70B of the IT Act, all cyber incidents must be reported within 6 hours of noticing or being brought to notice.

ZeroRespond SLA Compliance Engine:
The platform calculates: (Resolved Time - Detected Time).
• Under 6 Hours: COMPLIANT (recorded with remaining SLA buffer).
• Over 6 Hours: DEADLINE EXCEEDED (flags regulatory breach risk).

The auto-generated report includes a pre-formatted email draft ready for submission to incident@cert-in.org.in.

Will running the firewall containment commands permanently break our server?
No. The isolation commands (e.g., sudo iptables -I INPUT -j DROP) are in-memory firewall rules designed to halt active data exfiltration or lateral malware spread. Once the system has been verified clean and restored from backup, the final step in the playbook provides instructions to cleanly restore network access.
What if a playbook step does not apply to our specific setup?
Every step in the Playbook Runner has a "Not applicable" (Skip) button. If you skip a step, ZeroRespond marks it as skipped and logs the justification into the audit log. The case can still be successfully closed and a compliant report generated.
What if I make a mistake or run a command incorrectly?
You can click "Undo step" at any time on the current step to re-open it. You can also write specific observations into the "Analyst notes for this step" text field so future auditors understand why a particular deviation was made.
Can I edit or review the report before emailing CERT-In?
Yes! In the Incident Reports view, you can view the live HTML preview, download the court-admissible PDF compiled via WeasyPrint, and click "Copy reporting email" to review the exact notification text before dispatching it to incident@cert-in.org.in.
How do we test ZeroRespond without waiting for an actual attack?
ZeroRespond includes pre-packaged demo incidents (IR-08 Ransomware, IR-07 Brute Force, IR-06 Privilege Escalation, IR-05 File Integrity). You can step through their playbooks, upload sample screenshots as evidence, and run ./scripts/test_report.sh in your terminal to see real PDF generation in action.
